# 检验通过后直接写回润丰

## 业务范围

店内维修及员工外派：维修项目登记负责人，单人派工自动填入，多人派工须逐项选择本单维修工。项目名称及负责人在已提检／已通过后锁定，不能自检。提交完工、旧逐项完工及旧提检接口均有负责人校验。已有单人任务读取时自动补齐；历史多人任务缺少负责人时须先退回未通过项目、补齐后重新提检。

检验部分退回后，维修工点击“开始返工”，仅重新开工未通过项目；已通过项目及其检验记录保持完成。完成后重新提检，只检验待检项目。页面按同步任务所属轮次显示结果，不把历史成功记录用于本轮；本轮有退回时提示全部通过后才写入。

检验部分退回不创建写回任务；本轮全部通过后，在检验事务中保存不可变项目及人员编码快照。编码来自 users 的润丰绑定信息，姓名来自绑定的润丰员工档案。编码缺失时本次检验不提交，提示先办理绑定。外包任务保留既有检验流程，仅显示“润丰需人工登记”，不自动写入。

同步全量清单包含已结束各维修轮次和本轮项目，同一项目 ID 使用最新本轮记录，避免返工只选部分项目时漏掉以前项目。检验不再填写或强制记录工时，完结工单也不以工时为前提；历史工时记录保留，不写入润丰。接车编辑及接车签字预览移除费用录入与金额展示；历史费用字段和归档记录保留。

## 待确认与追加维修

首次开单仍将未拒绝、未安排的待确认项目以“【待定】”名称带入。开单后登记、同意或拒绝项目不会单独触发写回；只有后续本轮全部检验通过才生成完整清单快照。客户同意后安排维修沿用原 itemId：当前轮次未完成时加入本轮，已完成时建立追加轮次。已提检和已检验项目不能通过编辑项目修改或删除。

待确认卡片的客户决定与维修进度分开：安排后按当前任务显示待派工、待接单、待开工、维修中、暂停、待检验、检验通过；当前轮次不含该项目时读取最近历史轮次。缺少对应项目时显示“进度待核对”，不能凭 scheduled 标记推断完成。检验通过与润丰同步成功分别展示。

完整写回清单按 itemId 合并历史轮次和当前项目，不按名称去重。同意且检验通过的项目只保留正式名称，其余待确认项目保留一个“【待定】”条目。客户拒绝时仅保存本地决定；下一次允许的整单替换会移除拒绝项目。若润丰已有计价、工时或后续业务数据，则禁止整单替换，保留润丰原数据并显示错误，交由人工处理。没有后续整轮检验通过，就不自动同步后加的待定项目。

不补写或重试历史业务单，不设置车牌特例。

## 直写与事务

本功能由 H5 服务直接连接 SQL Server，不使用原开单轮询消费者。检验事务提交后立即触发后台直写；重启及每分钟的恢复扫描只由 H5 处理未完成任务，不要求润丰程序领取任务。原客户签字后的开单同步流程保留。

1. 按 pgd 锁定 qxwxb，要求空 wd 内单唯一；wd='1' 外单可暂缺，存在时须唯一，核验车牌、部门和 dh；以查到的真实内单 reid 生成幂等哈希，不再依赖开单消费者回填的 reid（它可能误填成明细编号）。任何歧义或交叉校验不一致仍阻止写入。
2. 检查幂等日志；同一来源与检验事件已成功则直接返回，内容不一致则拒绝。
3. 拒绝已删除、审核或结算单据，以及存在 qxpgmxb、cljgb、skxcb、qxthb 下游记录的单据。当前旧库无 qxwxb/qxwxmxb 触发器或指向项目明细的声明式外键；保护仍显式检查下游业务表。
4. 在同一事务中、任何删除之前锁定并检查内外单项目明细：qxwxb.xmfy/xmfy0 或任一项目的 dj、je、cb、gs、ywyje、uddec1、uddec2 非零，均停止覆盖并要求润丰人工处理。逐行判非零，正负抵消也阻止覆盖；无法取得检查结果则停止。材料、管理费等非项目金额不受影响。随后按旧库代码页验证名称／员工字符串可完整表达且不超过 varchar(100)，不截断。
5. 删除两张单据的 lb='项目' 全部明细，包括润丰手工项目，重新写入最终清单；保留材料、管理费等其他类别。
6. 内单 wxr 写“编码 姓名”，外单 wxr 留空。插入仅提供 wd、dh、lb、hh、wxr、Xh；数值列全部省略，不显式传 NULL 或零值，使用润丰数据库默认值。
7. 保留原费用合计一致性检查与更新步骤；新增保护要求被替换的项目金额、成本已全部为零，因此不再允许清掉已录入费用，fyhj/cbhj 中的非项目金额保持不变。
8. 按内单／外单分别保存成功幂等日志，在同一 SQL Server 事务提交，全部成功再提交；任意步骤失败整体回滚。

SQL Server 2000 只使用兼容语法。原子性覆盖内外单及幂等日志，不依赖 PostgreSQL 与 SQL Server 分布式事务。SQL 提交后若 PostgreSQL 回填失败，重试利用 SQL 幂等日志恢复，不重复删除重建。

同单按检验事件顺序串行处理；旧失败任务阻止后续任务越序。网络或数据校验失败最多自动尝试 5 次，之后管理员手动重试；等待初始开单编号回填不消耗失败次数。重试沿用原始快照，不读取后来修改的项目或员工绑定。等待条件为派工号及内部单号，不因缺失 reid 阻断。兼容旧版使用内单或外单 reid 的成功日志；纠正回填编号后重试不会重复替换。此匹配修复仅作用于检验写回，不批量改写历史开单关联或回执；开单消费者仍应回填 qxwxb.reid，而不是 qxwxmxb.reid。

## 部署与启用

默认关闭实际写入。当前本地已应用 PostgreSQL 迁移；已为用户指定的 A67527 创建待检验假数据并安装润丰幂等日志表。尚未提交检验或替换 A67527 项目。

1. 按正常流程运行 PostgreSQL `npm run migrate`，新增迁移包含员工绑定、repair_writebacks 任务表及 RLS；不要编辑已应用的迁移。
2. 在目标润丰数据库审阅并执行 `scripts/sql/runfeng-repair-writeback.sql`，创建专用幂等日志表。服务账号需具备指定业务表的读取、项目增删、指定合计字段更新及日志 SELECT/INSERT 权限；不在程序启动时执行 DDL。
3. 在润丰客户端核对已知内外单，确认空 wd 为内单、1 为外单。完成明确标记的业务测试单客户端验收后开启。
4. 配置 `RUNFENG_REPAIR_WRITEBACK_SOURCE` 为此 PostgreSQL 环境固定且唯一的英文来源标识（1–60 位字母数字、短横线或下划线，不随部署更换），再设置 `RUNFENG_REPAIR_WRITEBACK_ENABLED=true`，重启 H5 API。
5. 联调可配置 `RUNFENG_REPAIR_WRITEBACK_DISPATCH_ALLOWLIST=A67527`，仅此派工号会被后台领取和允许写入；当前本地使用此限制。空值表示全部单据，格式错误则全部拒绝。
6. 只有内单时先写内单；之后新建外单，管理员可点击“同步新增外单”，复用同一检验快照补写外单，已有内单成功日志防止重复重建。
7. 详情分别显示检验状态与润丰写回结果。停用时设置开关为 false 并重启；已完成检验及待处理快照保留。

原 API 路径保留。共享 RepairItemEdit/DispatchItem 增加 responsibleId（输入）及 responsibleName（服务端解析）；DispatchDetail.repairWriteback 返回同步状态。管理员重试入口为 POST `/api/dispatch/tasks/:orderId/repair-writeback/retry`，校验当前门店与角色并记录审计。没有已完成检验事件的历史完工单不会自动回填。

## 验证

- `npm run check`：领域规则、负责人、快照、SQL 仓储替身、TypeScript 和构建。
- `DISPATCH_TEST_ADMIN_URL=postgresql://... node --test test/dispatch.integration.test.mjs`：独立临时 PostgreSQL 数据库；覆盖未全通过不写回、缺员工绑定回滚、重复检验、快照不变、等待编号、失败重试权限、并发恢复和返工完整清单。不会调用真实润丰写入。
- `RUNFENG_WRITEBACK_SQL_TEST=true node --env-file=.env.local --test test/runfengRepairWriteback.integration.test.mjs`：真实 SQL Server 2000 方言测试，只创建本次唯一命名的 tempdb 临时表，复制零行表结构，插入“【测试】”数据后验证替换、内外单人员差异、非项目保留、费用合计、超长中文拒绝、事务回滚和幂等恢复，最后清理临时表。不会修改真实维修单或真实幂等日志表。

真实业务测试单的客户端验收与正式开关启用是上线步骤，不能用临时表集成测试代替。


## 审查修复

开启直写且单据在白名单内时，检验提交前对项目名称及人员字符串执行只读 SQL 校验，使用润丰实际代码页验证 100 字节限制；失败时检验事务回滚，可修改项目后重试。关闭直写时仍拒绝超过 100 字符的必然溢出内容。

管理员可先在润丰完成失败轮次的人工登记，再通过详情的“确认人工登记”填写核对说明。POST `/api/dispatch/tasks/:orderId/repair-writeback/resolve` 接收 `{jobId,reason}`，只处理指定失败任务，锁定并记录审计后改为 manual，解除后续轮次阻塞；不会删除失败快照或声称自动同步成功。

改派后重新接单保留原配件批次、备料与出库信息；新增配件独立申请。返工权限保持仅服务顾问或管理员可发起，维修工处理被分配的本轮项目；仓库各操作界面显示返工轮次及本轮领料批次。


改派只交接尚未提检的项目：单人团队自动指定新负责人，多人团队须逐项确认。待检验、已通过项目保留服务端保存的原维修负责人，允许新团队提交整单检验，润丰快照按各项目原／新负责人分别记录。检验退回的项目交给当前团队，单人自动指定，多人重新确认；已通过项目不变。改派和检验事件保存变更前后的项目，原负责人及历史维修参与人员继续不能自检。

## 本地测试模拟写回

设置 `RUNFENG_REPAIR_WRITEBACK_MODE=mock`、`RUNFENG_REPAIR_WRITEBACK_ENABLED=false`，重启本地开发服务。只允许 APP_ENV 为 development/test、NODE_ENV 非 production，且 DATABASE_URL 指向 localhost/127.0.0.1/::1；不满足时启动报错，不回退到真实写入。

模拟器读取真实检验产生的不可变快照，校验后在独立的 repair_writeback_simulations 表记录模拟结果。它不连接 SQL Server，不修改 repair_writebacks 的真实状态、错误、次数、快照，也不伪造首次开单派工号或润丰回执。没有润丰派工号的测试单也可以模拟；首次开单队列仍显示实际状态。切回真实模式后不会把模拟成功当成真实成功。

`RUNFENG_REPAIR_WRITEBACK_MOCK_RESULT=success` 为默认成功；设为 failure 并重启可注入失败。失败阻塞同单后续模拟轮次；切回 success 后由管理员点击“重新模拟”恢复。页面所有模拟结果均标注“测试模拟，未写入正式润丰”，模拟任务不提供“确认人工登记”。切回真实模式前仍需按正式流程核对真实历史队列。
