P1 改派后丢失原有个人配件约束

位置：server/domain/projectReassignment.mjs:29；整单改派也受影响，见 server/domain/dispatchPolicy.mjs:144。个人申请选择在 server/domain/individualRepair.mjs:35。

甲为“换滤芯”申请了尚未备齐的滤芯，本来不能开工。项目改派给丙后，申请仍保留在甲名下，而开工和提检只查丙的个人申请。丙查不到申请，被视为没有配件限制，能够开工并把该项目提交到待检验。

另一入口也能复现：整单从甲、乙改派给丙，丙选择“无需配件”接单，所有项目进入维修中并能整单提检，甲的未备料申请仍然保留。两种入口属于同一个交接漏洞，不重复计数。

修复方向：改派时显式处置或交接仍有效的个人配件申请，保留原申请、已备料和已出库证据；不要因更换维修工而把未处理申请隐式视为无需配件。不能简单改为所有人的申请阻塞所有人，否则会破坏个人独立维修。

复现边界：使用实际 domain 状态转换；HTTP 服务另有维修照片校验，本复现聚焦配件门槛。仓管并未卡死，任务仍在处理时可以继续备齐甲的申请并指定丙领取；甲离组后本人不能再维护申请。

脚本：/tmp/multiworker-parts-reassignment-review.mjs · 输出：/tmp/multiworker-parts-reassignment-review.log

P2 本人已提交或检验通过，仍被算作回审待处理

位置：shared/repairProgress.mjs:11。整单为回审时直接返回回审，没有继续判断本人的实际项目状态。

实际操作链：检验员将甲、乙的单发送回审 → 甲提交回审，乙仍在处理 → 检验员单独检验通过甲。甲的项目分别已是待检验、已完工，但两个阶段里甲的个人状态始终是回审。

详情页的 ownDone 已隐藏甲的操作按钮，却仍提示继续回审，容易让维修工反复打开无法处理的任务。这是“我的维修”分类、数量和状态展示问题；不据此声称独立的完工核对记录丢失。

修复方向：个人展示先识别已提交、已完工，只有本人仍待处理时保留回审。整单工作流阶段继续保持回审，不能用个人展示阶段替换后台动作阶段。

P2 撤销最后一个项目后，旧暂停会带入后来新增的项目

位置：server/domain/inspectionDeferred.mjs:43–45；服务入口 server/services/inspectionDeferredService.mjs:69 调用后直接保存结果。

实际操作链：甲、乙多人维修 → 甲暂停 → 检验员撤销甲唯一的已安排待定项目 → 甲离开当前维修名单，但 workerPauses 仍保留甲 → 顾问新增另一项目并分给甲。甲没有再次暂停，新项目却显示暂停，开工返回 409“当前暂停不能执行该操作”。
