P1跨门店只读列表泄露签字凭证纸质单通知允许跨店查看；原逻辑直接向管理员返回签字 token。凭证可用于公开签字接口，超出了只读权限。返回 token 前必须匹配门店，并满足管理员或负责人条件。兼任管理员的账号按完整角色集合判断。分页与非分页均有数据库回归测试。
P1普通员工上传后无法预览照片开单白名单没有匹配真实的 /api/files/:id/content 路径，读取被误判为未授权；未绑定编码的维修工也会被阻挡。白名单改为真实路径，原图和缩略图均恢复。原有文件归属和门店校验继续执行。
P2维修工、检验员查不到自己的草稿全员开单已开放，但列表仍只匹配分配的维修或检验任务，新草稿没有任务记录。同店范围内合并本人负责工单与已分配任务；验证跨店与其他员工的工单仍不可见。
P2无关工单保存改写签字时间保存工单、流转或同步会重复写入签字，旧逻辑每次把 signed_at 更新成当前时间。签字人未变化时不更新签字行，保留原始时间和签名图片引用。
P2生产查询误用测试档案缺少润丰连接配置时，车型/单位搜索和编码检查仍读取内置模拟数据，可能错误回填或报告编码可用。生产环境统一返回明确的 503 配置错误；开发与测试仍可使用模拟数据。
P2异常信息直接暴露给客户端未预期的数据库、文件系统或运行时异常被原样返回，可能泄露内部结构与实现细节。未知异常返回通用 500 信息，详细错误保留服务端日志。明确的业务错误仍提供可操作提示。
P3非法 JSON 顶层值触发内部错误null、数组和基本类型虽是合法 JSON，却不符合接口对象契约，可能导致解构或后续代码异常。统一入口返回 400；空请求体继续按空对象处理，兼容无参数操作。

照片问题：文件已上传，读取权限被误拒绝

上传和显示照片是两个独立请求。POST /api/files 已获得开单权限，所以能保存照片；页面随后请求图片内容时，错误路径使白名单匹配失败，返回 403。

修复前的白名单

GET /api/files/:id
GET /api/files/:id/thumbnail

与实际前端请求不匹配。

实际请求与修复后的白名单

GET /api/files/:id/content

缩略图增加 ?size=thumbnail，路径不变。请求进入后，仍须通过文件归属、门店及用途检查。
