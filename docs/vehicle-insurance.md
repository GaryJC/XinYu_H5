# 公司车辆保险

车辆管理支持手工编辑保险生效日、到期日及承保明细，或上传公司车辆承保明细 `.xlsx`。管理员才能修改或导入；管理员和服务顾问接收续保提醒。

## Excel 导入

点击“导入保险 Excel”，选择原表，预览后点“确认更新”。以“新车牌号”匹配本店车辆，匹配到则更新车型及保险明细，未匹配则新建。已有品牌、启停状态和车辆 ID 保留，表外车辆不删除；新建车辆的品牌取车型列，之后可人工完善。原车号只作为历史备注，不用于自动合并车辆，避免原车号中多个车牌串造成误匹配。

保留列：原车号、新车牌号、车型、登记及年审时间、保险终保时间、车辆状况、车辆使用部门、产权归属、投保付款单位、承保公司。年审列保留原始文本，不猜测不规范日期。保险列须含完整起止日期，例如 `2026.9.3-2027.9.2`。

单文件最多 3 MB、500 条，展开上限 16 MB。空行忽略，重复车牌、日期无效、缺少要求的列都会报错。保存使用整批事务；重复上传更新同一车辆，不重复建车。只把上传内容作为数据读取，不执行表内公式、宏或指令。

## 出车及提醒

按北京时间自然日判断：到期当天仍有效，次日过期。无完整保险日期、未生效或已到期均禁止申请及批准／确认出车，最终检查在服务端车辆行锁内进行；已出车可以正常还车。

启用车辆在剩余 30、7、1 天和到期当天推送提醒，过期后另推一次“已到期”。首次导入或服务恢复时，补发当前所在阶段，不补发更早阶段。同店有效管理员、服务顾问去重接收；发出前重新检查保险日期、车辆启用状态和接收人岗位。更新到期日后旧待发提醒取消。平台返回不确定结果不盲目重发。

沿用 `DISPATCH_NOTIFICATION_MODE` 和现有钉钉配置。disabled 不运行；mock 仅开发／测试；生产须为 dingtalk。每小时扫描一次到期索引，每分钟处理至多 10 个通知，按门店合并岗位同步；无业务请求中的定时扫描或新增客户端轮询。停机关闭时等待在途处理完成。

## 发布

先应用 `202611100002_company_vehicle_insurance.sql`，再发布服务和前端；迁移仅新增列、通知表和索引，不虚构旧车辆保险。上线后在车辆管理导入原表，尚未录入保险的车暂不能出车。保留原车牌历史及用车关联。无需变更既有用车申请、审批或收车接口路径。

测试使用临时数据库和模拟通知，不代表钉钉真实送达已验收；本次未向生产库导入数据或发送真实推送。
