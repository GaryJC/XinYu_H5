# 接单即开工与配件需求

维修工确认接单时必须明确选择“无需配件”“选择或填写配件”“拍摄手写清单”之一。常见配件可快速添加，数量、单位可修改，也可手动添加其他配件。照片使用现有拍照／相册、压缩、鉴权存储和预览能力；无需 OCR 或额外说明。仅登记需求，不创建领料、采购或库存扣减。

确认接单在同一事务中保存需求、实际登记人和时间，将待维修项目转为维修中。已通过检验的项目、已有实际开工时间保留；不再需要维修工点击“开始维修”。维修中或暂停时可补充／修改配件，每次操作留痕。已有待开工任务和检验退回项目可直接提交完工，保留通过项目与未知的历史时间标记；原逐项目及整单开工接口继续用于兼容。

需求作为 `partsRequirement` 保存在任务、派工事件与返工轮次快照中。新一轮返工重新登记需求，不继承上一轮需求。`accept` 动作增加必填需求；`record-parts` 用于补充需求。旧客户端未提供需求时会收到明确的 400 提示，需要更新前端后接单。照片上传接口接受 `purpose: parts`，生成独立类型 `repair_parts_photo`；与维修过程照片分开，限制本店、当前处理人、允许状态及当前轮次。重试沿用上传请求 ID，登记只能引用本单、本轮已保存清单照片。

派工单信息从原委托单和当前任务读取，展示派工号、派工日期、进厂日期、托修单位、车型、车号、里程、主修人、质检人、竣工时间；主要作业及增修项目单独列出。没有值时明确显示未填写／未记录／待平台回填，不从示例照片推测业务数据。按用户选择，本轮工种、班长留空，不增加填写入口。原费用、签字、结算与平台同步保持原流程。

新增迁移 `202610150004_parts_requirements.sql`，已应用本机开发库，正式环境需先迁移再更新服务。本轮代码留在 dispatch 工作区，不提交、不推送、不部署。验证包括 `npm run check`、派工及返工独立数据库集成测试，以及 375、390、430、1280px 布局、快捷配件／手填／照片方式的浏览器验收。浏览器测试使用本地模拟单与项目自带测试图片；真实钉钉相机、相册及软键盘仍需真机验收。

提交完工（整单及旧版逐项提检入口）前必须已有至少一张本轮 `repair_progress_photo`，在派工事务内校验；历史轮次、接车和手写配件清单照片不计入。检验退回仍属当前轮次，可保留本轮记录。维修工在派工单信息下可查看并放大本单接车／车损照片，不展示行驶证和签字图片。外包任务由本店服务顾问或管理员记录维修照片后提检。
