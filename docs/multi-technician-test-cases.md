# 多人维修测试用例与执行记录

执行日期：2026-10-26。范围：派工分工、个人维修、配件、暂停恢复、提检、部分检验、回审返工、并发与写回。本清单区分领域测试、真实 PostgreSQL 集成测试、浏览器和钉钉真机，跳过不算通过。

## 测试环境与约定

- A、B、C：同店有效维修工；S：服务顾问；W：仓管；I：独立检验员；X：跨店或未分配员工。
- 默认工单含 P1→A、P2→B，已接单且项目维修中；每个用例独立构造数据。
- 集成测试只使用本机 PostgreSQL，新建唯一名称临时库、应用迁移、结束删除；通知 mock，不调用生产润丰写入。
- 断言不仅检查操作返回，还检查其他人的项目未变化、版本、负责人、暂停、提检人及完成时间；数据库用例检查重新读取、事件、通知、照片归属、写回任务。
- P0：权限、数据隔离、错误完结或重复写入；P1：正常业务无法继续或状态错误。

自动化定位：`I` = `test/individualRepair.test.mjs`；`D` = `test/dispatch.integration.test.mjs`；`P` = `test/projectDispatch.test.mjs`；`E` = `test/repairItemEditing.test.mjs`；`R` = `test/repairReview.test.mjs`；`T` = `test/dispatchTechnicians.test.mjs`；`W` = `test/repairWriteback.test.mjs`；`N` = `test/repairRounds.test.mjs`。下表“通过”指对应自动化断言通过，不代表钉钉真机通过。

## 本轮修复与复现证据

先新增失败测试，再改领域代码。F1–F6 在修复前均失败，F7 单独补测也确认失败，F8 由真实 Chrome 流程复现；日志位于本机 `/tmp/repair-multi-repro.log`、`/tmp/repair-multi-repro2.log`。

| 缺陷 | 修复前表现 | 修复位置 |
| --- | --- | --- |
| F1 | 暂停中的个人备齐后 resumeStage 仍是待开工 | individualRepair：合并配件操作更新后的个人暂停状态 |
| F2 | 共同配件未齐连暂停、恢复、编辑都被禁止 | individualRepair：配件门槛仅作用于施工/提检动作；前端保留暂停恢复按钮 |
| F3 | 最后一人提交覆盖当前检验领取人 | individualRepair：已有待检批次保留领取信息 |
| F4 | 新一批部分提检沿用上一批检验领取人 | individualRepair：新批次清理三项领取信息 |
| F5 | 部分检验通过或退回将整单暂停改成维修中 | dispatchPolicy：保留暂停阶段 |
| F6 | 他人的未分配项目阻止已提交项目检验通过 | dispatchPolicy：只校验本次通过项目的归属 |
| F7 | 旧多人整单暂停点击恢复后仍是暂停 | individualRepair：整单暂停交由整单恢复转换处理 |
| F8 | 任一项目提检即隐藏全部维修项目，未完成工作无操作入口 | DispatchTaskDetail：部分待检时同时显示维修与检验区域 |

此外更新过时集成测试和浏览器脚本：多人分别提交及个人照片、备齐后追加批次计数、已备齐禁止修改、签字必填数据和接车照片、派工计划项目参数、逐条消费通知队列。没有放宽业务校验来迁就测试。

```sh
node --test test/individualRepair.test.mjs
npm run check
DISPATCH_TEST_ADMIN_URL=postgresql://postgres:postgres@127.0.0.1:54322/postgres node --test test/dispatch.integration.test.mjs
# 浏览器环境另设 DISPATCH_UI_TEST=true、DISPATCH_PLAYWRIGHT_MODULE、DISPATCH_CHROME_PATH，详见 scripts-reference.md。
```
