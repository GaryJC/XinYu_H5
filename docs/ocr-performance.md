# OCR 耗时排查

行驶证、车牌和 VIN 在浏览器端准备识别图片：最长边最多 2560 像素，JPEG 质量从 92% 调整到最低 80%，目标大小约 1.4MB。优先保留文字清晰度，达到最低质量后不再继续压缩，因此复杂图片仍可能超过目标大小。小尺寸且体积合适的 JPEG/PNG/WebP 保持原文件；钉钉 WebView 无法解码或压缩时保留原文件，并记录 `fallback: true`。

行驶证保存准备后的照片，随后向原 `/api/ocr/vehicle-license` 接口发送 `{ fileId }`，不再从手机重复传图片。服务端先校验文件访问权限和照片类型。OSS 使用有效期 5 分钟的私有签名链接调用阿里 OCR，不向客户端返回链接；明确配置为 local 的存储直接读取已保存的图片。原 `{ imageBase64 }` 调用方式继续可用。

## 查看耗时

浏览器控制台：

- `[ocr-image]`：准备图片耗时、原始和输出字节数、是否回退、是否超过目标大小。
- `[ocr-request]`：文件上传、OCR、识别记录保存、车辆档案查询的各次请求总耗时，以及对应的 `requestId` 和 `serverTiming`。

服务器日志 `[request-timing]`：按 `requestId` 关联单次请求，包含 API 路径、HTTP 状态、服务端总耗时和各阶段毫秒数。响应也包含 `X-Request-Id` 和 `Server-Timing`，可在浏览器网络面板查看。

| 阶段 | 含义 |
| --- | --- |
| `body_read` | 服务端读取请求体并解析 JSON |
| `image_store` | 保存图片到已配置的存储 |
| `file_record` | 创建文件数据库记录 |
| `file_access` | 校验已上传行驶证的访问权限 |
| `ocr_source` | 获取签名链接或读取本地图片 |
| `aliyun_ocr` | 阿里 SDK 调用，包括连接、传输/云端取图和识别等待 |
| `ocr_record` | 保存识别记录 |
| `vehicle_lookup` | 公司车辆档案查询和车型、所属单位匹配 |
| `server_total` | 从服务端收到请求到准备返回 JSON |

如果 `aliyun_ocr` 长，瓶颈在服务端到阿里的调用链路；该数值不能进一步区分网络和阿里算法处理。如果浏览器总耗时明显大于 `server_total`，应检查手机网络、代理和传输耗时。`body_read` 也可能包含部分上传等待，不能把它与上述差值直接相加作为精确上传耗时。跨请求的阶段不能相加成单次请求耗时。

日志只记录时间、大小、路径和请求 ID，不记录图片、识别内容、车牌、VIN、令牌或签名 URL。真实提速幅度应在部署后使用相同照片和网络环境比较。
