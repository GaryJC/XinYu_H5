# 前端加载与构建体积

运行 `npm run check` 后执行 `npm run analyze:bundle`，可查看各入口的 JS/CSS 依赖总量、gzip 估算值和静态资源总量。报告会递归计算静态依赖并去重；工作台统计包含应用外壳和工作台页面，不能只用入口 JS 的大小代表首屏。

## 2026-11-03 优化

在同一工作区、相同依赖和构建环境下对比（十进制 MB/KB）：

| 指标 | 优化前 | 优化后 | 减少 |
| --- | ---: | ---: | ---: |
| 全部静态资源 | 18.47 MB | 10.34 MB | 44.0% |
| 工作台首屏 JS/CSS | 2.17 MB | 1.62 MB | 25.3% |
| 工作台首屏 JS/CSS gzip 估算 | 760 KB | 517 KB | 31.9% |

首屏统计不包括 API 数据、业务照片、后续交互和字体下载；gzip 是逐文件压缩的估算，不是线上网络实测。新增 manifest 不计入静态资源总量。

- 打印预览、模板和字体样式在生成预览时加载，PDF 引擎仍在生成 PDF 时加载。字体不再以内联 base64 混入 JS。
- 保留 Noto Serif SC 的两个字重和全部 Unicode 字形分片，仅输出 WOFF2，移除重复的 WOFF。目标仍是 Chrome 80 / Safari 13，旧 WebView 的 CSS 兼容配置保持不变。
- 工作台、客户签字和供应商入口分别加载，外部客户入口不再拉取整个工作台。
- 修改联系及车辆信息时才加载新增车型/单位组件及拼音字典。
- 派工负荷图表展开时才加载 ECharts 和请求负荷数据；文字标签与图表实现分离，避免列表间接导入图表库。

图表和 PDF 分块仍约 600 KB（未压缩），属于交互时加载的资源，不计入首屏。不通过关闭构建告警掩盖这些体积。

构建配置使用 Vite 的[按需分块和静态资源处理](https://vite.dev/guide/assets)及[构建 manifest](https://vite.dev/config/build-options.html)。分析脚本会检查三个入口是否意外静态依赖打印、图表或拼音模块，以及是否重新输出重复 WOFF。

## 部署缓存

Nginx 直接提供前端时，采用 [部署指南](./deploy-ecs.md) 中 `/assets/` 的一年 immutable 缓存配置，并保持 HTML 和版本接口 `no-store`。仅带内容哈希的构建资源适用长期缓存，缺失资源返回 404。修改文档不会自动更新现有服务器的 Nginx 配置。
