# 出车申请与公司车辆管理

## 使用

- 所有钉钉在职、未停用员工均可进入“出车申请”。无业务岗位角色的员工使用基础员工身份，仅可使用出车功能。
- 申请人选择启用车辆，填写事由及可选备注。本人即驾驶员，不代他人申请或还车。
- 本店任一其他管理员点击批准后，系统自动记录审批人及审批时间；随后，申请人上传公里数照片并确认出车；还车时上传另一组照片并确认。两次时间均由服务端自动记录，界面按北京时间显示。
- 公里数只保存照片，不识别或计算。每阶段须选择 1–9 张照片。
- 管理员可在“车辆管理”录入、编辑、停用和启用车辆。停用后不能新申请或出车，已出车的申请仍可还车。历史单据保留申请时车辆信息。
- 审批不能自审；没有另一位管理员时，申请保持待审批。驳回必须填写原因，出车前申请人可取消。
- 未绑定润丰编码的维修工可以先使用出车申请，进入维修功能仍需完成绑定。

## 数据及接口

迁移：`202610290001_vehicle_trips.sql`。新增独立车辆、申请、附件关联及操作记录表，并初始化 8 辆公司车辆到 `shop-hq`。按车牌去重，不覆盖已有记录；不会关联维修客户车辆档案。

- `GET /api/company-vehicles`：本店启用车辆；管理员使用 `?all=true` 查看停用车辆。
- `POST /api/company-vehicles`、`PUT /api/company-vehicles/:id`：管理员维护车辆，传入车牌、品牌、车型、启用状态。
- `GET/POST /api/vehicle-trip-requests`：查看有权访问的申请或新建申请。
- `GET /api/vehicle-trip-requests/:id`：详情、照片、审批人及时间、历史签字及操作记录。
- `POST /api/vehicle-trip-requests/:id/{approve,reject,cancel,depart,return}`：流程操作。
- `POST /api/vehicle-trip-requests/:id/attachments`：上传出车或还车阶段的公里数照片；上传和确认分开，失败不推进状态。
- `GET /api/files/:id/content`：复用图片预览路径，出车附件使用独立鉴权；未确认附件仅上传人可见，已确认附件仅申请人及本店管理员可见。

申请创建、上传和流程操作必须传入稳定的 `requestId`，重试相同内容返回首次结果；同编号不同内容返回 409。数据库事务和行锁保证并发审批只有一次成功。确认出还车只接受本人上传且属于该申请及阶段的附件，服务端时间不会被重试覆盖。

## 验证与上线

- `npm run check` 执行单元测试、类型检查及构建。
- 使用 `DISPATCH_TEST_ADMIN_URL` 指向本机测试 PostgreSQL，运行 `node --test test/vehicleTrips.integration.test.mjs`。该测试创建独立临时库、执行迁移，并在结束时删除临时库；不指向生产数据库。
- 上线前执行新增迁移，并确认钉钉应用可见范围及员工详情接口授权覆盖所有在职员工。
- 无须新增云服务凭证，沿用现有图片存储配置。不包含车辆预约、占用冲突控制和导出。

## 钉钉通知

- 提交申请：通知本店其他有效管理员；管理员本人申请不会收到自己的审批提醒。
- 批准、驳回：通知申请人，驳回消息包含原因。
- 取消申请：通知本店其他有效管理员。
- 确认出车、确认还车：通知实际审批人。
- 点击消息直接打开对应出车申请；申请人仅能查看本人申请，管理员仅能查看本店申请。

迁移 `202610290002_vehicle_trip_notifications.sql` 新增独立通知事件和发送队列。业务操作、操作记录及通知事件在同一事务内保存；相同请求重试、并发审批不会重复入队。上传照片不发送通知。

沿用 `DISPATCH_NOTIFICATION_MODE`、`DISPATCH_APP_URL`、`DINGTALK_AGENT_ID`、`DINGTALK_APP_KEY`、`DINGTALK_APP_SECRET` 和企业 ID 配置。生产使用 `dingtalk` 模式；管理员名单先从钉钉同步，失败不会回退到本地名单。`disabled` 模式保留待发送事件；`mock` 仅限开发／测试。

后台每 5 秒处理队列。发送前再次检查申请阶段、门店及接收人当前权限：已审批／取消的旧审批提醒、已出车的旧批准提醒等会取消发送。明确可重试的失败最多尝试 5 次；已经受理的消息查询发送结果，发送结果不确定且无任务编号时不会自动重发，须核对钉钉记录。没有其他管理员时，申请仍保存，通知事件记录失败原因并重试。

验证：`test/vehicleTripNotifications.test.mjs` 覆盖接收人、消息链接及发送重试；`test/vehicleTrips.integration.test.mjs` 使用隔离数据库验证事务、并发去重、通讯录失败、通知租约及结果查询。设置 `VEHICLE_TRIP_UI_TEST=true` 并提供 Playwright／浏览器路径可验证通知链接直达详情及权限隔离。测试不向真实员工发送消息。
