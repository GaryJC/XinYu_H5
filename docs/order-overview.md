# 工单全览与照片 Word 导出

服务顾问和门店管理员可从“工单全览”查看本店全部工单，按原有归档筛选条件查询，打开详情查看客户车辆资料、签字、项目、配件、OCR、同步、出库、结算、待修项目客户决定、历次维修及流程留痕。

## 照片分类

- 接车时：行驶证、维修前车况、补充照片、纸质委托书。
- 维修时：维修过程和配件照片。
- 维修完成：维修人员在上传照片前明确选择“维修完成”。在提交完工之前上传，沿用现有维修照片权限及维修轮次校验。

历史过程照片继续属于“维修时”，不会根据工单状态自动更改分类。已替换照片和电子签名图片不纳入照片文档。

每张工单可一键导出全部照片，也可勾选一个或多个分类合并导出一个 `.docx`。照片按分类、上传时间排序，最多每页 4 张，双栏大图排版，等比例缩放并嵌入文档。文档仅保留照片，不添加车牌、派工号、分类、页码、时间、维修人或说明文字；单张照片仍保持半行宽。单次最多 300 张，超限提示分分类导出；图片读取失败则整次失败，不生成缺图文档。

## 接口和权限

- `GET /api/work-orders/:id/overview`：仅服务顾问和门店管理员，可读取同店工单。不会返回客户签字令牌。
- `POST /api/work-orders/:id/photo-document`：参数 `{ categories: ['reception', 'repair', 'completed'] }`，可选其中任意非空子集。重新读取最新工单并校验每张照片读取权限。
- `GET /api/order-photo-documents/:token.docx`：随机 256 位临时下载凭证，有效 5 分钟，进程重启失效。用于手机浏览器及钉盘下载，响应禁止缓存。同一用户的新导出替换旧下载链接。

钉钉手机端沿用保存到钉盘及预览能力，失败时保留临时下载链接供重试。桌面端自动发起下载，同时提供下载链接。

## 上线

先应用 `supabase/migrations/202610270001_completed_repair_photos.sql`，增加允许的文件分类，再发布应用。不需要重写旧照片数据。发布前运行 `npm run check`。

验证包括分类去重、被替换照片过滤、角色和跨门店访问拒绝、分类参数校验、Word 图片嵌入和分页、缺图报错，以及维修完成照片删除时的轮次保护。用 11 张横图、竖图和长图生成样例，实际渲染为 3 页（4/4/3），检查中文显示及比例。手机钉钉的钉盘保存仍需真机验收。
