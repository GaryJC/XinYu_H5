# 维修工润丰员工编码绑定

维修工首次登录时，后端按钉钉姓名精确查找润丰 `dbo.ygxxb`，只接受 `wxg=1` 且 `zt=在职` 的档案。一个候选自动绑定；多个候选由员工选择，展示编码、部门和状态；没有候选或润丰不可用时停留在匹配界面，可重试或联系管理员核对姓名及档案。

绑定前会话只允许查询本人身份及办理绑定，其他业务 API 返回 403。绑定接口重新查询本人候选，不接受任意员工编码。姓名和员工角色来自服务端已认证用户，不接受客户端指定。其他应用角色不受影响。开发维修工身份也遵守绑定要求，需要使用可匹配的开发数据验证。

绑定保存到应用 PostgreSQL `users` 的 `legacy_employee_code/name/department/bound_at` 列。后续登录复用，不再次查询润丰；改绑需要管理员处理，员工不能自行覆盖。重复或并发相同确认可安全重试，不同确认冲突返回 409。对润丰只执行读取。

接口：`GET /api/auth/employee-binding` 返回 `EmployeeBindingStatus`；`POST` 同路径接收 `{ employeeCode }`。业务身份 `UserProfile` 新增可选 `legacyEmployeeCode`。候选接口只返回员工编码、姓名、部门和状态。

上线前先通过既有迁移流程应用 `202610180001_technician_employee_binding.sql`，再发布服务端和前端。迁移不预先绑定已有维修工，原有会话也会受到服务端门禁。上线后核对唯一姓名自动绑定、李富强等同名档案手动选择、刷新及再次登录免匹配、无候选及网络失败不放行。绑定属于员工编码映射，不向润丰维修项目写入维修人。
