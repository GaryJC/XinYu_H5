# 检验待定

检验可选择通过、退回或待定。待定原因必填；同一项目不能同时退回与待定。待定项目从本轮活动项目中移出，原项目编号、维修过程、来源轮次及检验请求编号保存在待定记录和派工事件中，不计作检验通过或退回。其他项目通过或全部待定时，本轮可结束并结算。

仅该项目最近一次判为待定时的原检验人，且仍具有本店独立检验权限，可在任务详情的待定列表直接派工，无需登记客户同意；客户待确认项目仍沿用原权限及确认流程。派工选择维修工和预计完工时间，本轮结束后开启追加轮次，进行中则加入本轮。待检验时需先处理当前检验。任务列表提供“待定”筛选，包含已结算但仍需跟进的工单；待定计数包含未安排和已安排但未通过的检验待定项目。

未派工项目可删除／不再维修；已派工项目在再次检验通过前可撤销。原因必填，不删除历史，不自动退库或修改费用。撤销只移除对应活动项目，重新计算任务状态，最后一个活动项目撤销后可结束本轮。已领取配件保留交接记录，通知维修工和仓管人工核对退料。

检验接口新增 `deferredItemIds`、`deferredReason`，原路径不变。`pending_repairs` JSON 使用 `source: inspection`、`inspectionState: pending | scheduled | completed | cancelled`，缺少来源字段的数据仍视作原客户待确认。操作复用待确认接口的 `schedule`、`decline`，新增 `cancel`；服务端按来源和实时角色校验。只扩展现有 JSON，无数据库结构迁移。

润丰按原项目编号合并各轮次，未通过的检验待定项添加单个【待定】前缀，再次通过后去掉前缀；删除和撤销以终态记录排除历史项目，防止旧轮次将其带回。仍有活动项目时，删除或撤销仅同步对应项目；若撤销使本轮结束，则生成完整快照以同步所有已检验通过项目，允许明确标识的空项目清单。尚未回写待定前缀时优先使用初始开单快照定位；没有已知位置时在润丰核对原名及待定名，仅唯一匹配才删除，项目已不存在则记录成功，不阻塞后续同步。已有完整快照确认未发布的项目无需删除。撤销完成快照缺少员工绑定时保存为失败任务，补齐绑定后可重试，保留完整同步范围；原有计价、审核、结算保护仍执行。取消本地维修不等待外部预检成功，写回失败在同步记录中展示，可重试或人工处理。正式润丰送达必须以写回任务的成功状态为准。

待定通知顾问和管理员，派工通知维修工，撤销通知维修工、顾问、管理员，以及涉及配件时的仓管。通知与业务变更同事务入队，发送前检查待定状态、当前负责人、门店和维修轮次。重复请求幂等，旧待定派工消息在撤销后失效。

验证：`npm run check`；数据库测试 `test/inspectionDeferred.integration.test.mjs` 仅在显式设置本机 `DISPATCH_TEST_ADMIN_URL` 时运行，创建并清理独立临时库，不发送真实通知。

原检验人归属随待定记录保存（sourceInspectorId、sourceInspectorName），已有记录从最近一次“检验待定”历史中的 actorId 读取；不使用整单当前检验员或姓名猜测身份。派工、删除和撤销均校验原检验人，管理员也不能代操作。其他本店检验员及管理员会看到提示和“提醒原检验人处理”按钮，点击后将带工单入口的钉钉通知加入队列。同项目一分钟内防重复提醒，请求重放幂等；提醒不改变维修进度或回写队列。原检验人缺失、停用或无独立检验权限时明确报错；发送前再次校验接收人归属、权限及项目处理状态，已处理的旧提醒不再发送。此规则针对检验待定项目，客户待确认项目保留现有角色权限。
